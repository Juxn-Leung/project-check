# 真实项目行为评测

固定项目和任务见 [cases.json](cases.json)，首次记录见 [2026-10-26 评测](../../docs/evaluations/2026-10-26.md)。这些任务验证从需求到实现、讲解和验收的实际行为；工具的单元测试不能替代它们。

## 两类评测分开记录

1. **全新接入**：为每个案例建立隔离目录，检出固定上游版本，加载固定 Skill 快照。在新代理上下文中只给项目位置、任务提示和正常工具权限，观察首次接入、实现与交付。记录协调提示，不能把它算作自主完成。
2. **已接入项目复验**：复制保留了配置、测试和基线的交付项目，固定新 Skill 快照。执行 index、execute、resume 和讲解复核。这衡量重复使用，不包含首次业务理解与测试编写时间，不能和全新接入耗时直接比较。

评测运行前记录 Skill 每个资源文件 SHA-256、上游 commit、实际子目录及依赖版本。所有运行、失败尝试、命令、开始/结束时间和修正原因分别保存。环境不能运行时记录阻塞，不能改成假报告。

## 记录与判定

| 观察项 | 必须记录的证据 |
| --- | --- |
| 操作成本 | 总耗时、命令数、用户问题/介入、协调者澄清/指导；未测指标写未测 |
| 需求与实现 | 需求来源、任务范围、修改前基线、实际产品 diff |
| 验收 | 原生报告、场景映射、断言审阅、真实依赖、失败与修复轨迹 |
| 恢复 | resume 前后命令回执、日志和原生证据的 hash/mtime；实际是否重执行 |
| 历史保护 | 原运行产物 hash 不变，创建的新数据/进程被清理 |
| 讲解 | 只读摘要回答“改了什么、影响哪里、未验证什么”；再看有来源的行为前后对比图 |
| 认知效果 | 代理审阅与真人反馈分别记录；不能把代理自评写成真人好懂 |

只要缺少原生证据、源码过期、测试断言不足、未知副作用被盲目重跑或自有进程遗留，不能判为完整通过。故障复验覆盖：进程非零而报告全绿、清理失败、源码变化、原生证据损坏、无结束回执的真实中断，以及忽略 SIGTERM 的服务子进程。

对比图使用已阅读基线与当前代码中的行为，明确展示同一操作的前后结果。没有旧行为依据时保留未知，不为好看而编造截图、流程或通过状态。

每次功能/可靠性改动至少重跑相关案例与针对性故障。安装包在独立目录完成打包、安装和 Python CLI 调用；禁止用主仓库源码碰巧可用来代替已安装资源验证。
